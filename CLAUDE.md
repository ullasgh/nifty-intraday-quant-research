# nifty_quant

Quantitative research repo for Nifty intraday strategies. Hard rules:

1. **Tests first, and DUAL independent test suites.** For each unit: the lead writes a spec under `specs/`; then **DeepSeek** (`deepseek-worker-agent`) and **Luna** (`worker-luna`) EACH write their own separate test file from that spec alone — neither sees the other's tests, and neither sees an implementation, because none exists yet. Two independent readings of a spec catch different defects, and any disagreement between the two suites is itself a finding worth chasing. **DeepSeek also writes implementation**; **Haiku workers** (`worker`, model haiku) implement too, one agent per file. **Opus** (lead) and **DeepSeek** act as critic and verifier, re-running everything rather than trusting reports. The lead does planning, spec-writing, review and verification, and hand-writes implementation only for review-derived edits (dead-code removal, justified `# pragma: no cover`), which must be stated as such.
   - Corollary, learned the hard way: an implementer may **never** edit a test to make it pass. If a test looks wrong it gets reported, not changed. And a failing statistical test is never fixed by changing the seed — see rule 8.
2. Never modify, move, or add anything under `data/` — it is source data, 2.1 GB, already committed to git.
3. float32 at rest, float64 in motion: never accumulate P&L or returns in float32.
4. Bars are left-labelled: the bar labelled T covers the interval [T, T+60s). `ts` is an int64 epoch-seconds UTC value with no timezone attached; convert with `pd.to_datetime(ts, unit="s", utc=True)` then `.tz_convert("Asia/Kolkata")`.
5. Never assume a fixed 375-bar session stride — sessions vary (e.g. Muhurat trading session is 60 bars, disaster-recovery/shortened sessions can be 105 bars). Always index via explicit day offsets, never a fixed row-count-per-day assumption.
6. Never forward-fill bars at rest — NaN means "no bar occurred". Any gap-repair/fill must be opt-in and visible at the call site, never silent.
7. The panel's `present` mask (a bar exists) and `tradable` mask (a bar exists AND is usable for trading, e.g. passes liquidity/halt checks) are distinct concepts and must never be conflated or merged into one.
8. **No threshold is a hand-chosen constant.** Every cutoff must be derived from a measured null distribution on real data, and the derivation recorded next to the value. Enforced because the first `adjustment_audit` shipped with a reasoned-not-measured threshold (`0.35`, ~1.42x) and produced 8,217 false positives across all 149 symbols while every synthetic test passed.
9. **Coverage checks flake; power checks do not.** A "does the CI contain X" assertion fails with probability ~alpha *per comparison* regardless of effect size — asserting it across 5 buckets flakes 23% of the time on correct code. A detection check with large effect-to-SE ratio is effectively deterministic. Prefer asserting on a single spread, or on the false-positive RATE across >= 30 seeds. **Never fix such a test by changing the seed** — that is the same failure as re-tuning a strategy default to make a null test pass.
